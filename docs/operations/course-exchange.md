# Course exchange: two tested profiles

Use `/operations/courses` with an institution-scoped `portability.manage` grant. Supply the **offering UUID**, not a course code or upstream registration ID. Export reusable chapter content only. Review text and links for rights and personal information. Keep the original source package separately.

| Format | Supported | Not supported |
|---|---|---|
| SCORM 1.2 static asset subset | ZIP with root `imsmanifest.xml`, IMS 1.2 packaging namespace, ADL `scormtype="asset"`, one organization, ordered flat items, one referenced plain `.txt` file per resource. Chapter titles and UTF-8 body bytes round-trip. | SCORM runtime/SCO, HTML/JS, LMS tracking, nested items, prerequisites, SCORM 2004 or full schema conformance. Organization labels, source identifiers and filenames are not preserved. |
| Adin `adin-text-1` | ZIP with root `course.json`, ordered chapters with `title`, `file`, `links`. Each link has `title` and absolute HTTPS `url`, no credentials or query. Exportable links are single-revision, unrestricted, non-downloadable materials. | Binary uploads, captions, body materials, schedules, access restrictions, alternate versions or assessments. |
| IMS Common Cartridge / Moodle `.mbz` | No versions qualified. Use an external approved conversion to a supported profile and compare it in a **draft**. | Native Moodle restore, IMS CC activities, quizzes, question banks, grade exchange. No Moodle instance or vendor interoperability was certified by the local round trip. |

Package intake reads entries in memory, never extracts paths or fetches URLs. Max 1 MiB upload, 50 flat lower-case ASCII named `.txt` assets plus manifest, 65,535 uncompressed bytes per entry, 512 KiB total. Absolute/nested paths, missing/duplicate/unreferenced files, encrypted ZIPs, non-text content, XML DTDs and unknown activity elements are rejected. Module positions are renumbered from 1 in document order. All-or-nothing import requires an **empty draft**; a second import conflicts rather than duplicating chapters. No accounts, teaching assignments, grades or registration records are imported. Review before publishing via the usual academic process.

**Demonstration:** In a fresh demo environment prepare two empty draft offerings, A and B. From `tests/Fixtures/operations` run `zip /path/to/sample.zip imsmanifest.xml field.txt` (or `course.json field.txt` for native). Import into A, download the corresponding format, then import the downloaded ZIP into B. Compare ordered titles and exact body bytes; for native verify “Library catalogue” points to `https://library.example.test/catalogue`. Check `course.imported` and `course.exported` in the audit trail. A draft with unsupported materials returns a validation error rather than silently substituting a file. **Scope:** unrelated activities outside chapters/materials are never selected by this export.

Require PHP ZIP, DOM/libxml and mbstring in the deployment image. No connector credentials are needed. LTI launch, library authentication, SSO and external grade/roster push are not part of these profiles. Test a connector only when the institution supplies an enabled configuration, approved test tenant, credential custody and an agreed contract.
