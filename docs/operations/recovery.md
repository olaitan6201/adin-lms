# Restore rehearsal and recovery checklist

Run `bash docs/operations/rehearse-recovery.sh` from the checkout with PHP dependencies, PostgreSQL client/server tools (`pg_config`), `tar`, and a normal non-root Unix account. The script creates a new owner-private `.agent-work/recovery.*` cluster, accessible only through its private Unix socket. It does not use a running database, live object storage, external mail or production credentials.

1. Migrate and seed a disposable source. The fixture writes a synthetic CBT response and a revision through `ExamSession::save`, plus a text object and its checksum metadata.
2. Take a PostgreSQL custom-format dump and private-object archive while the fixture is quiescent. Restore into a second empty database and a separate object directory, with restore errors fatal.
3. Compare response IDs, question IDs, revision numbers, saved answers and timestamps byte-for-byte, and compare the restored file digest with the restored `files` row. The script fails on any mismatch or if the two response rows are missing.
4. Save the run output and version, inspect the evidence directory, then retire the disposable artefacts according to local policy. The script stops its own cluster on exit. The fixture is synthetic; the test's temporary dump is unencrypted and **not** a production backup procedure.

**For a real installation:** agree recovery owners, backup intervals, retention, RTO and RPO. Configure monitored scheduled DB backups (and WAL/PITR or engine equivalent when required), versioned private object backups, encrypted offsite copies and separately escrowed keys/config. Confirm successful restore with the actual database engine, storage backend, application revision and key versions. Coordinate a DB/object consistency point; a DB dump alone does not capture private files. Alert on missing, late or unreadable snapshots and perform periodic isolated drills.

On incident, preserve source evidence, authorise a recovery point, isolate a restore destination, disable external connectors/notifications and keep workers paused. Restore application/config/keys, DB and matching object snapshot; reconcile sample response revisions, object hashes, constraints, users/permissions, audit chain and published results. Exercise login, course access, download, autosave and grading with authorised test users. Record actual elapsed time, last recovered save and discrepancies. Obtain release authority before cutover, retain a rollback target and reconcile subsequent official upstream changes. No production cutover, MySQL restore, storage-vendor restore or service-level measurement is implied by the PostgreSQL drill.
